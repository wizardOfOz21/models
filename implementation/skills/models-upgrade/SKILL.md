# Совершенствование моделей

Сначала прочитай [метамодель моделей](_models/models-metamodel/model-ru.txt) и её [подсказки](_models/models-metamodel/tips.txt). Метамодель — основа этого скилла. Следующие инструкции — надстройка над ней для совершенствования моделей в ходе работы над проектом.

Модели предназначены для совершенствования в ходе работы. Развивай их параллельно проекту, опираясь на выявленные при работе недостатки и новые знания. Изменения моделей должны помогать основной задаче и не отвлекать от её выполнения: вноси относящиеся к ней улучшения по ходу работы, без отдельного этапа пересмотра всех моделей.

## Локальные копии

Модели, используемые проектом, хранятся копиями в его папке `_models/`. Они устанавливаются копированием; новые версии из хранилища устанавливаются вручную. Совершенствуй именно локальные копии: здесь модели разрабатываются параллельно проекту.

Папка `_models/` самого скилла содержит используемую им копию метамодели; изменения моделей проекта вноси в `_models/` соответствующего проекта.

Позже локальные улучшения при необходимости могут быть перенесены в хранилище моделей. Такой перенос находится за пределами этого скилла.

## Версии моделей по проектам

В разных проектах могут использоваться разные версии одной модели: локальные копии развиваются независимо. Веди рядом с `SKILL.md` текстовый реестр [model-versions.txt](model-versions.txt), чтобы сохранять сведения об этих версиях.

При обновлении модели в любом проекте обязательно обновляй её версию и связанные сведения в этом реестре. Если записи для этой копии ещё нет, добавь её. Обновление модели включает обновление реестра рядом с этим скиллом.

Для каждой копии указывай проект, путь к модели, её название, версию, дату и ник из `version.txt`, а также время последней проверки. Если часть сведений отсутствует, явно отмечай это, не дополняя их предположениями. Обновляй запись при чтении или изменении модели в проекте. Полное сканирование компьютера выполняй по запросу; отмечай область поиска и ограничения доступа. Не считай ранее записанные сведения о других проектах актуальными без проверки и не удаляй запись только потому, что её путь временно недоступен.

Реестр учитывает различия версий; он не требует выравнивать их между проектами или автоматически заменять локальные копии.

В реестре храни версию, дату и пользователя в одной строке: `Версия: v1.0.0 | Дата: 14.11.2026 | Пользователь: g.gasaev`. Формат самого `version.txt` остаётся трёхстрочным.

## Изменения и версии

Уточняй модель по существу обнаруженной проблемы или нового знания; при необходимости обновляй связанные подсказки и термины. Сохраняй различие между содержанием модели и советами по её реализации.

При изменении модели поднимай её версию по SemVer. Diff для выбора повышения считай относительно последнего коммита, учитывая все текущие изменения этой модели. До следующего коммита пересчитывай одно повышение по совокупному diff, а не повышай версию заново после каждой правки. Для новой, ещё не закоммиченной модели задай начальную версию.

В `version.txt` записывай на отдельных строках версию, дату и ник пользователя согласно подсказкам метамодели. Используй известный ник пользователя из контекста проекта или настроек Git; если его нельзя установить, уточни у пользователя.

В результате основной работы кратко отмечай существенные улучшения моделей и их новые версии, не превращая это в отдельный отчёт.
